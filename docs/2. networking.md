## Network Overview
- The system is physically connecting to the home network only via the Xiaomi R3P router running OpenWrt.
- IPv4-only network model (no IPv6 in use).

## DNS & Traffic Flow
The lab uses a dedicated DNS stack (Pi-hole + Unbound) running on the server, rather than relying on the router. 
I find this more appropriate than handing the responsible to the router because: 
- The Xiaomi R3P is preserved for pure packet routing, while the more powerful server handles the resource-intensive task of DNS filtering and recursive resolving.
- Ad-blocking is treated as an opt-in feature rather than a network-wide mandate.
	By configuring Tailscale to override client DNS settings, connecting to the VPN acts as an on/off switch for the server's Pi-hole/Unbound stack. Disconnecting from the VPN disables it. 
This enables:
- Strict filtering and internal resolution on personal devices only ***when desired***, not forced.
- Standard internet compatibility for other LAN clients (smart TVs, guests, IoT) via the router's default upstream DNS.

## Remote
- Remote access is restricted to the Tailscale network only.
- No public access endpoints exposed.

## Etc
- Default gateway is the R3P router, which is also handling DHCP and NAT.
- The LAN is currently flat (no VLAN segmentation).

## Future Segmentation Plan
The network is planned to move from a flat LAN model to a segmented model if and when more public exposure or more devices are in play.

Planned additions:
- VLAN-based segmentation
- Dedicated DMZ zone for internet-facing services
- Isolation between internal devices and exposed services
- Controlled inter-zone access only

This will be introduced only when external exposure is required and is not part of the current active network design.
